# 共通仕様（3サイト共通）

`gaburi.md` `nagi.md` `sumitsugi.md` はこの文書を前提にしている。実装前に必ず読むこと。

## 0. この仕様書の読み方

**この仕様書は「何を作るか」しか書いていない。「どう見せるか」は書いていない。**

- 色、書体、余白、構図、モーションの質感、描画の手法 —— **すべて実装者が決める。**
  16進値も、寸法比も、フォント名も、この文書には出てこない。出てこないのは書き忘れではない。
- **文章は指定する。** これは内容であって、デザインではない。そのまま使うこと。
- **振る舞いの規則は指定する。** 料金の計算、満室の決め方、積める上限。これも仕様であってデザインではない。
- **完成の条件は指定する。** 検証可能な形で書いてある。全部通すこと。

判断に迷ったら「これは内容か、規則か、見た目か」で切り分ける。見た目ならあなたが決める。

## 1. 成果物の形式

- **1ファイル。ビルドもライブラリも使わない。** 素の HTML / CSS / JS。
- Artifact に載せるため、`<!doctype>` `<html>` `<head>` `<body>` は**書かない**。
  ファイルは `<title>` から始め、以降は自由（`<link>` / `<style>` / マークアップ / `<script>`）。
- **外部アセット禁止。画像も動画も CDN も使えない**（CSP で外部ホストが遮断される）。
  **Google Fonts だけは例外**として許可されている。
- JS の先頭で `document.documentElement.lang = 'ja'` を立てること。

## 2. 写実の要件（この仕様でいちばん大事なところ）

**写真のように見えること。イラストではない。**

いま作られている3本はどれもイラスト的で、平坦な塗りと輪郭線でできている。それを捨てる。

外部の画像は一枚も使えないので、写実は**ブラウザの中で描いて**到達するしかない。
手法は問わない —— WebGL のシェーダ、Canvas 2D の重ね塗り、CSS のグラデーションと影、
どれでも、混ぜてもよい。**そこはあなたが決めること。**

満たしてほしいのは次の点：

- **輪郭線を引かない。** 物の縁は、明度差と接地影で立たせる。線で囲った瞬間に絵になる。
- **平坦なベタ塗りを使わない。** どの面にも、光源に対する傾きぶんの階調がある。
- **材質が面ごとに違って見えること。** 金属の鋭いハイライト、塗りの映り込み、
  紙や布の拡散、肉の焼き目のむら、ガラスの反射と透過 —— 光の返し方がそれぞれ違う。
- **光源の向きが全要素で一致していること。** 影の方向、ハイライトの位置、面の明暗が、
  ひとつの光を指していること。ここが崩れると、何を描いても嘘になる。
- **影に硬さの変化があること。** 接地する場所は硬く濃く、離れるほど滲んで薄い。
- **カメラの痕跡を入れること。** 被写界深度、わずかな粒子、周辺光量の低下。
  ほんの少しでいい。入れると「写真で撮ったもの」に見えはじめる。

**やりすぎに注意。** 金属を鏡にしたり、影を真っ黒にしたり、反射を入れすぎたりすると、
今度は 3DCG の見本に見える。目標は「よく撮れた商品写真」であって「レンダリングのデモ」ではない。

## 3. 技術上の決まりと、踏みやすい穴

以下は見た目の指示ではなく、**踏むと壊れる**ことが分かっている落とし穴。

1. **スクロール量は JS が測って配るだけ。** `scroll` は `requestAnimationFrame` で
   1フレーム 1回に束ねる。毎イベント描画するとカクつく。
2. **固定面の高さは実測する。** `100svh` の sticky を `window.innerHeight`（＝`100vh`）で
   割ると、アドレスバーが出入りするモバイルで進行度が 1 に届かない。
   `travel = section.height - stage.offsetHeight` を使うこと。
3. **`position:sticky` を後続のクラスで潰さない。** 同じ要素に後から `position:relative` を
   当てると後勝ちで sticky が消える。sticky は既に絶対配置の包含ブロックになっている。
4. **日本語のフォールバックに中国語フォントを混ぜない。** `Songti SC` などが混ざると
   字形が中国語になる。`lang="ja"` も併せて必須。
5. **`prefers-reduced-motion`** では固定を全部解き、絵は完成形で静止させる。
   動きを止めるだけだと、何も起きない画面を何スクリーンも送らせることになる。
6. **横スクロールを出さない**（`scrollWidth - clientWidth === 0`）。
7. `body` にトークン由来の `background` を必ず置く。透明だと外側の地色を拾う。
8. 色の定義を `@media` や `[data-theme]` の**中だけ**に書かない。未指定テーマで色が落ちる。
9. `:focus-visible` に見える状態を与える。
10. リサイズと `document.fonts.ready` で測り直す。

### 描画の負荷について

写実に振ると描画が重くなる。次を守ること。

- **スクロール中に 60fps を保つこと。** 重い描画は解像度を落とす、
  変化のないフレームは描き直さない、など手は任せる。
- WebGL を使う場合、devicePixelRatio は 2 で頭打ちにする。
- モバイル（390×844）でも破綻しないこと。

## 4. どのサイトにも共通する完成の条件

1. **desktop(1440×900 light) / dark / mobile(390×844) / reduced-motion** の4条件で
   描画し、横スクロールが 0、`pageerror` と console error が無いこと。
2. **文字が、その背後にあるものに対して常にコントラスト比 4.5 以上**であること。
   背景が動く画面では、**100点以上サンプリングして最低値を測り**、報告に含めること。
3. **描いた要素が、その背後の面と区別がつくこと。**
   塗りが地色と同一になっていないか、実際に画素を測って確かめること。
   （過去に、チーズの色とセクションの地色がまったく同じ値で、
   輪郭だけが残って「切り抜かれた牙」に見えた事故がある）
4. **スクリーンショットを自分で Read して目で見ること。**
   数値が通っていても絵が破綻していることがある。おかしければ直してから再検証する。

**この環境には日本語フォントが入っていない。** Google Fonts も届かない。
検証時は、使う書体を Google Fonts の `&text=` API で取得し、data URI として
埋め込んだ CSS に差し替えてから読み込むこと（`mkfonts.py` が同ディレクトリにある。
書体名を書き換えて使える）。差し替えないと字形が中国語のフォントになり、判断を誤る。
